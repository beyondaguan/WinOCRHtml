## 1. 定位

WinOCR 桌面端（原生重写版）：**截图 → OCR → 翻译** 的效率工具。
- 原生 UI：**Rust + Slint**（不使用 HTML/WebView2，用户已否决 Tauri 路线）
- 本地优先：OCR/翻译默认离线能力优先，云 API 仅作可选回退
- 目标形态：托盘常驻小工具，绿色 zip 分发

## 2. 三层架构（严格单向）

```
┌─────────────────────────────────────────────────────┐
│ UI 层  app/src/ui/                                   │
│   main_window.slint（声明式工作台）                    │
│   mod.rs（include_modules! + 回调绑定 + 线程编排）      │
└──────────────┬──────────────────────────────────────┘
               ▼ 只允许向下调用
┌─────────────────────────────────────────────────────┐
│ Services 层  app/src/services/                       │
│   hotkey ✅  capture ✅  ocr ✅  translate 🚧          │
│   ai ✅  attach ✅  persist ✅  collect ✅            │
│   export ✅  migrate ✅  tts 🚧  tray ⬜              │
└──────────────┬──────────────────────────────────────┘
               ▼
┌─────────────────────────────────────────────────────┐
│ Core 层  app/src/core/  （不依赖上两层）               │
│   types（Lang/WorkMode/AppState/AppEvent）           │
│   event_bus（mpsc 广播）  config（JSON 读写）          │
└─────────────────────────────────────────────────────┘
```

**依赖规则**：UI → Services → Core；禁止反向依赖；禁止跨层（UI 不直触 Core，Services 之间互不依赖）。
Cargo 体现：`app/` 单 crate 内用 `mod` 分层 + `crate::` 路径约束，靠纪律与评审保证方向。

## 5. 关键数据流（已实现部分）

### 5.1 截图流（P1-1，✅）

```
Alt+Q（winocr-hotkey 线程，WM_HOTKEY）
  │ slint::invoke_from_event_loop
  ▼
UI 线程 on_capture ──► spawn capture 线程
                         │ select_region()：冻结背景(BitBlt 屏→内存DC)
                         │   → 全屏 popup 窗(WS_POPUP|TOPMOST) 显示背景
                         │   → 拖选(LBUTTONDOWN/MOUSEMOVE/LBUTTONUP) / Esc 取消
                         │   → 防重入 CAPTURE_BUSY；选区 <4px 视为取消
                         ▼
                     capture_region_gdi(rect)   ← BitBlt + GetDIBits 24bpp（去行对齐）
                         ▼
                     save_png → %TEMP%\winocr_capture_<ts>.png
                         ▼
                     ocr::recognize_file(path)   ← PP-OCR(ort, det/rec) 主引擎；失败→系统 OCR 兜底
                         ▼ slint::invoke_from_event_loop
UI：状态条 "OCR 完成 · N 字符" + 左栏 ocr-src = 识别文本（translate → ocr-out 见 P1-3）
```

### 5.2 线程模型

| 线程 | 职责 | 消息循环 |
|---|---|---|
| 主线程 | Slint 事件循环（winit）+ 全部 UI 属性/回调 | winit |
| winocr-hotkey | RegisterHotKey(Alt+Q) + GetMessageW 循环 | Win32（阻塞） |
| capture（按需） | 蒙版窗（Win32 消息循环）→ 抓屏 → PNG → **PP-OCR 推理**（失败兜底系统 OCR） | Win32 消息循环 + ort 推理（后台线程） |
| winocr-selection-hook（常驻） | 装 `WH_MOUSE_LL` 低级鼠标钩子 + `GetMessageW` 循环（二者必须同线程）；回调只做「读坐标 → 比位移 ≥6px 判拖选 → `try_send` → 立刻返回」（详见 §5.4） | Win32（阻塞） |
| winocr-selection-work（常驻） | 消费拖选事件 → 十步取词流水线（延时 / 剪贴板 / 模拟 Ctrl+C）→ 取到非空文本才回调 UI | 无（mpsc 阻塞等事件） |

**跨线程约定**：
- 回 UI 线程：一律 `slint::invoke_from_event_loop` + `Weak::upgrade()`（Weak 为 Send）
- 热键注册结果：mpsc channel（start 内 recv_timeout 3s 等结果）
- 蒙版内部状态：`static Mutex<Option<OverlayState>>`；裸指针不可 Send，**DC 句柄在 static 中存 isize**
- 防重入：`CAPTURE_BUSY: AtomicBool`（连按 Alt+Q 不叠蒙版）
- WinRT（OCR）在后台线程调用：线程内先 `CoInitializeEx(MTA)`；`IAsyncOperation::get()` 阻塞等待

```
ocr-src（左栏）→ translate(P1-3 Argos 离线) → ocr-out（右栏）→ 复制
```

### 5.4 划词取词流（services/attach.rs）

> **来源纠错（留档）**：`services/attach.rs` 原为无实现的占位 stub，旧注释与 §4 表声称的移植来源
> `rust-reference/selection_window.rs`（"划词部分"）**是错的** —— 该文件实为**截图选框窗**
> （`select_region()` 等，已移植进 `services/capture.rs`）；全仓库没有任何桌面原生划词实现。
> 本模块是**从零实现**；唯一借鉴的是 `rust-reference/src/window.rs` 里剪贴板 API 的**用法思路**
> （那是老版 winapi crate，符号名与本工程 windows-sys 不同，未照抄任何类型名）。

**双线程模型**（两线程均为进程生命周期常驻，不做 stop；开关走 `Attach::set_enabled(bool)` 原子变量）

| 线程 | 职责 |
|---|---|
| `winocr-selection-hook` | 安装 `WH_MOUSE_LL` 低级鼠标钩子 + 跑 `GetMessageW` 消息循环（**二者必须同线程**：低级钩子经该线程的消息队列派发）。回调内**只做**：读坐标 → 与 mousedown 比位移（≥6px 判为拖选）→ `try_send` → 立刻返回 |
| `winocr-selection-work` | 消费事件：左键按下直接转发 `ClickDown`；拖选命中则跑十步取词流水线，取到非空文本才回调 `Hit` |

- 线程间用 `mpsc::sync_channel(64)` + `SyncSender::try_send`（`mpsc::Sender` 没有 `try_send`）。
- **用时红线（本节核心设计要点）**：低级鼠标钩子回调超时会被系统**静默卸载且多半不恢复**，
  故回调里绝不允许出现剪贴板 / 延时 / 翻译等耗时操作，一律丢给工作线程；缓冲满就丢事件 ——
  丢一次划词远比卡住**全局鼠标**可接受。
- 钩子回调是 `extern "system"` 自由函数（无法捕获闭包环境），它的状态（发送端 + 开关）放在
  **安装钩子那个线程**的 `thread_local!` 中，不引入全局可变 static。

**十步取词流水线**（每一步都有存在理由）

1. 前景窗口属于本进程 → **跳过**（避免在自己的主窗口 / 气泡里拖选也弹气泡）
2. `sleep(120ms)` —— 让宿主应用先完成选区绘制与内部状态更新（浏览器 / Electron 的合成选区尤其需要）
3. 保存原剪贴板文本（`Option<String>`）
4. **清空剪贴板作哨兵**
5. `sleep(30ms)` —— 释放剪贴板占用，目标应用才能拿到所有权
6. `SendInput` 模拟 Ctrl+C（按下顺序 Ctrl↓ C↓ C↑ Ctrl↑）
7. `sleep(80ms)` —— 复制是异步的，等目标应用把选中文本写进剪贴板
8. 读回剪贴板
9. 还原原剪贴板（`Some(t)` → 写回；`None` → 清空），不打扰用户的复制历史
10. trim 后非空才算命中，否则丢弃（**不弹气泡**）

> **第 4 步「哨兵」的价值**：区分「真的没选中」与「复制到了残留的旧文本」。若省略第 4 步，
> 密码框 / 终端等**不响应 Ctrl+C** 的窗口会让第 8 步读回**上一次的旧内容**，于是弹出显示旧文本的气泡。

**浮层调用协议（已冻结，UI 层必须遵守）**

```text
foreground_hwnd()  记录宿主前台窗口
  → bubble.show()                        首次 show() 会短暂抢焦点
  → overlay_make_nonactivating(TITLE)    打 WS_EX_NOACTIVATE 与 WS_EX_TOOLWINDOW + 置顶（不显示）
  → overlay_place(TITLE, x, y)           定位 + 显示（SWP_SHOWWINDOW），不激活、不改尺寸
  → restore_foreground(prev)             把焦点还给宿主
此后每次命中只调 overlay_place；隐藏 = overlay_place(TITLE, -32000, -32000)
永远不要调用 Slint 的 hide()
```

> **为什么禁用 `hide()`**：winit 的 `apply_diff` 只要窗口 flags 有任何 diff，就用缓存值**整体重写**
> `GWL_STYLE` / `GWL_EXSTYLE`，把 `WS_EX_NOACTIVATE` 与 `WS_EX_TOOLWINDOW` 清掉并 `ShowWindow` 抢焦点
> （完整证据链见 `技术.md` §5 踩坑表对应两条）。

**公开面（12 个函数 + 3 个类型）**

- `Attach`：`new` / `start(on_event)`（**幂等**：重复调用不会起第二个线程）/ `set_enabled(bool)` /
  `enabled()`，另提供 `impl Default`。`enabled` 初值 **false** —— 划词是可选功能，若默认开启会在
  用户不知情时对全局拖选注入 Ctrl+C（会覆盖用户剪贴板），必须由 UI 读配置后显式开启。
- 浮层辅助：`overlay_make_nonactivating` / `overlay_place` / `overlay_rect` / `screen_size` /
  `foreground_hwnd` / `restore_foreground`。其中 `overlay_rect` 返回窗口**真实物理像素**矩形，
  供 UI 做「点击气泡外部即隐」的命中判定与越界回退（Slint 的 `width/height` 是**逻辑像素**，
  高 DPI 下与物理像素不等）。
- 剪贴板门面：`copy_text_to_clipboard(text) -> bool`（供气泡「复制译文」等 UI 动作使用）。
- 类型：`SelectionHit { text, x, y }`、`SelectionEvent::{Hit, ClickDown}`。
- 剪贴板 helper（get / set / clear / OpenClipboard 重试）与钩子内部结构（`RawEvent` / `HookSink` /
  钩子回调）**保持私有**，只暴露上述语义明确的函数；非 Windows 平台整体 no-op（各公开函数均有
  `#[cfg(not(windows))]` 兜底实现，保证可编译）。
