## 二、产品定义

### 2.1 产品目标

| # | 目标 | 衡量标准 |
|---|---|---|
| G1 | **采集效率最大化** | 从"看到生词"到"进入采集队列" ≤ 2 次点击 |
| G2 | **零干扰阅读** | 主路径（截图→译文）不离开工作台；导出/历史不打断当前任务 |
| G3 | **信息可审计** | 每条采集记录可追溯原文、译文、时间、来源项目 |

### 2.2 用户画像

**Primary**：医生（泌尿外科），阅读英文医学文献，需要：
- 快速截图翻译（Alt+Q）
- 标记生词/生句 → 导出到 Anki 复习
- 不离开当前阅读上下文

**Secondary**：其他专业人士（法律、科研），类似采集场景

### 2.3 用户故事

| # | 角色 | 场景 | 行为 | 价值 |
|---|---|---|---|---|
| US-1 | 医生 | 阅读 PDF 文献时遇到生词 | 划词 → 气泡显示译文 → 一键采集 | 不中断阅读流 |
| US-2 | 医生 | 阅读段落需要理解 | Alt+Q 截图 → 看双栏原文/译文 → 选中单词采集 | 快速理解+采集 |
| US-3 | 医生 | 一天工作结束 | 切换到采集队列 → 按项目筛选 → 导出到 Anki | 批量管理采集内容 |
| US-4 | 医生 | 需要深度理解术语 | 工作台选中单词 → 点击"问 AI" → 获得解释 | 术语深度学习 |
| US-5 | 医生 | 回顾之前翻译 | 切换到历史 → 高级筛选 → 重新采集或导出 | 知识回溯 |

## 三、页面架构决策

### 3.1 方案对比

| 维度 | 方案A：工作台为主 + 抽屉/模态 | 方案B：保留双栏 + 强化单页 |
|---|---|---|
| **核心理念** | 工作台是唯一主界面；历史/采集/导出作为侧边抽屉或模态弹出 | 6 个页面平级，通过导航轨切换 |
| **主路径效率** | 极高 — 截图后永远在工作台，采集/导出不离开 | 中 — 需要切换页面才能看采集/导出 |
| **信息密度** | 低 — 一次只能看一个辅助面板 | 高 — 表格/列表可并排展示 |
| **改动幅度** | 大 — 需要重写布局系统、新增抽屉组件 | 小 — 仅强化现有页面内部结构 |
| **用户认知负荷** | 低 — "工作台=一切"，符合采集管道定位 | 中 — 需要理解 6 个页面各自职责 |
| **实现复杂度** | 高 — 抽屉动画、模态管理、状态同步 | 低 — 复用现有 if 条件元素切换 |
| **扩展性** | 好 — 新面板可作为新抽屉加入 | 差 — 页面增多后导航轨拥挤 |
| **键盘操作** | 优 — 抽屉可快捷键呼出 | 中 — 需要切换页面快捷键 |

### 3.2 推荐：方案A（工作台为主 + 抽屉/模态）

**理由**：

1. **定位对齐**：v2.0 定位是"前端采集管道"，不是"学习系统"。管道 = 线性流动，工作台是管道的主体，采集/导出是下游出口。方案A 让"采集"动作发生在工作台，符合"看到即采集"的管道直觉。

2. **用户场景**：医生阅读文献时，90% 时间在看原文+译文，10% 在管理采集。方案A 让 90% 场景不切换界面，10% 场景用抽屉快速呼出。

3. **数据流自然**：截图 → OCR → 翻译 → 采集，全部在工作台完成；导出是"把采集队列打包送走"，用模态确认即可。

4. **竞品参照**：Google Translate 的"主页=翻译面板"、DeepL 的"主界面=翻译+历史侧边"，都是工作台为主。

**风险与缓解**：

| 风险 | 缓解措施 |
|---|---|
| 抽屉空间受限（360px 气泡已证明） | 抽屉宽度 ≥ 480px，支持拖拽调宽 |
| 模态打断阅读流 | 采集确认用轻量 Toast，不用模态；仅导出用模态 |
| 实现复杂度高 | 分阶段：先做抽屉，后做模态；复用现有 ScrollView 组件 |

## 五、页面规格

### 5.1 工作台（Capture）— 主页面

#### 布局结构

```
┌─────────────────────────────────────────────────────────┐
│ 顶栏 50px                                                │
│ [蒙图翻译] [文件] [在线图片] | [from▾][⇄][to▾] | [⚙]    │
├─────────────────────────────────────────────────────────┤
│ 导航轨 60px │ 工作区（horizontal-stretch: 1）            │
│             │                                           │
│  ▣ 工作台   │  ┌─────────────────────────────────────┐  │
│  ✦ AI对话   │  │ 空状态引导卡（无内容时）             │  │
│  ↻ 历史     │  │ 或                                   │  │
│  📌 采集     │  │ 双栏视图（有内容时）                 │  │
│  📤 导出     │  │ [原文栏 50%] | [译文栏 50%]         │  │
│  ⚙ 设置     │  │                                     │  │
│             │  │ 候选词面板（截图后自动出现）         │  │
│             │  └─────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────┤
│ 状态条 32px                                              │
│ [● 已就绪] [● OCR] [● 翻译 Argos] [● 缓存 0/500]       │
└─────────────────────────────────────────────────────────┘
```

#### 核心组件

| 组件 | 类型 | 职责 |
|---|---|---|
| 顶栏 | 固定 50px | 语言对选择、截图触发、设置入口 |
| 导航轨 | 固定 60px | 6 个页面入口，当前页高亮 |
| 双栏视图 | 互斥（if ocr-src != ""） | 原文/译文并排展示 |
| 空状态引导卡 | 互斥（if ocr-src == ""） | 三入口：截图/文件/粘贴 |
| 候选词面板 | 条件（candidates.length > 0） | 截图后自动列出可采集单词 |
| 状态条 | 固定 32px | 实时状态、引擎、缓存、进度 |

#### 交互行为

| 触发 | 行为 | 结果 |
|---|---|---|
| Alt+Q / 点击"蒙图翻译" | 启动截图 | 截图 → OCR → 翻译 → 回填双栏 |
| 原文栏选中单词 + 点击"采集" | 采集当前选中 | 单词+译文入采集队列，Toast 反馈 |
| 候选词卡片点击"加入" | 采集该候选词 | 单词+译文入采集队列，Toast 反馈 |
| 译文栏点击"🔊 朗读" | TTS 朗读译文 | 播放语音 |
| 译文栏点击"复制" | 复制译文到剪贴板 | Toast "已复制" |
| 点击"问 AI" | 打开 AI 面板 | 右侧面板展开，带当前原文上下文 |
| 点击"查看队列" | 打开采集抽屉 | 右侧抽屉展开 |

#### 状态变化

| 状态 | 触发 | UI 变化 |
|---|---|---|
| 空闲 | 启动后 / 清空后 | 显示空状态引导卡 |
| 截图中 | Alt+Q 按下 | 状态条显示"截图中…" |
| OCR 中 | 截图完成 | 状态条显示"OCR 中…" + 进度条 |
| 翻译中 | OCR 完成 | 状态条显示"翻译中…" + 进度条 |
| 完成 | 翻译完成 | 双栏显示原文/译文，候选词面板出现 |
| 错误 | OCR/翻译失败 | 状态条显示错误信息，原文栏显示错误提示 |

#### 与其他页面关系

- 工作台 → 采集队列：选中单词"采集" → 写入采集队列（不切换页面）
- 工作台 → AI 对话：点击"问 AI" → 右侧面板展开（带上下文）
- 工作台 → 历史记录：每次翻译完成 → 自动写入历史（后台）
- 工作台 ← 采集队列：采集队列"打开工作台" → 回填原文/译文到工作台

> 与原型差异：无 3D 翻面动画（改两态切换）、blur 遮罩改 ••• 点阵、记忆法/搭配/易混词（无数据源）暂缺、☆收藏改✕关闭、顶部加单词引入输入行。
> 视觉为原型专属配色，**不跟随主窗主题**。

#### 入口与角标

- 导航轨第 5 项「🎓 学习」→ `open-study()` 回调 → 打开独立 StudyWindow 窗口（880×640，进程级常驻、默认隐藏）
- 红底白字角标显示今日到期词数（>99 显示 99+，0 不显示）；启动时与窗口每次 refresh 时刷新
- 主题令牌（bg/surface/accent 等 10 色）在 refresh 前按当前 config 主题填充，缺省浅色 C

#### 顶栏：单词引入接口（UI 入口）

- LineEdit 输入/粘贴单词，回车或「引入」按钮 → `services::study::introduce_word`（唯一入口：归一化 → 查重 → 分级 → source 标记）
- 已在生词本 → 直接出卡（提示「已在生词本」）；新词 → 入库并立即出卡（提示「已引入」）
- 出卡后后台链：词典增强（音标/英英/词根/例句，`enrich_async`）+ 中文释义（空才翻 Argos，`translate_zh_async`），完成回填
- 会话进行中引入 → 追加到当前队列队尾并跳转；无会话 → 新建单词会话

#### 三态流转

| 态 | 内容 | 动作 |
|---|---|---|
| ① 摘要 | 大数字到期数 + 生词本总数 + 待复习队列预览（word · 释义） | 「开始复习」（到期 0 时禁用，显示"今日已完成 ✓"） |
| ② 正面 | 单词大字 + 音标 + 🔊发音/🐢慢速 + 档位/项目徽章 + 中文释义自测遮罩（•••，点击显示/隐藏）+ 进度条 | 点击卡片翻面 |
| ③ 答案面 | 📖英英释义 → 🀄中文释义（①②③编号）→ 🧩词根 → 💬例句 → 📎采集原句 → ⏰复习计划，各节可朗读 | ◀上一词 / 下一词（跳过）▶ + 四档自评：忘记0/模糊3/记得4/容易5 |

- 评分后自动推进下一词；队列走完回摘要页，角标同步归零
- 发音复用 TTS 回退链（edge-tts → onecore），en-US，慢速档 SAPI rate=-4

## 六、关键交互流程

### 6.1 截图采集完整旅程（从 Alt+Q 到导出）

```
用户动作                    UI 响应                    数据状态
─────────                  ─────────                  ─────────
1. Alt+Q                   → 显示截图蒙版              → 空闲
2. 框选区域                → 截图完成，状态条"OCR 中"  → 截图数据
3. （等待）                → OCR 完成，状态条"翻译中"  → OCR 原文
4. （等待）                → 翻译完成，双栏显示        → 原文+译文
                           → 候选词面板出现
5. 选中单词 + 点击"采集"   → Toast "已采集"            → 采集队列+1
6. 点击"查看队列"          → 右侧抽屉展开              → 显示采集表格
7. 点击"导出"              → 打开导出模态              → 显示导出配置
8. 选择格式 + 路径         → 点击"导出"                → 文件写入
9. （完成）                → Toast "导出成功"          → 导出完成
```

**关键决策点**：
- 步骤 4 后，用户可选择：继续截图 / 采集单词 / 问 AI / 查看队列
- 步骤 5 的"采集"不切换页面，保持工作台上下文
- 步骤 6 的抽屉可快速浏览，点击条目可回填工作台

### 6.2 划词翻译旅程

```
用户动作                    UI 响应                    数据状态
─────────                  ─────────                  ─────────
1. 鼠标拖选文本            → 气泡出现在选区右下        → 取词完成
2. （等待）                → 气泡显示"翻译中…"         → 翻译请求
3. （等待）                → 气泡显示译文              → 译文完成
4. 点击"复制译文"          → Toast "已复制"            → 剪贴板写入
5. 点击"采集"              → Toast "已收藏"            → 采集队列+1
6. 点击"工作台"            → 气泡收起，主窗口置前      → 回填双栏
7. 点击"关闭"              → 气泡移出屏幕              → 隐藏
```

**关键决策点**：
- 步骤 3 后，用户可选择：复制 / 采集 / 打开工作台 / 关闭
- 步骤 5 的"采集"直接入队，不打开采集页面
- 步骤 6 的"工作台"将划词结果转为工作台上下文

### 6.3 AI 问答旅程

```
用户动作                    UI 响应                    数据状态
─────────                  ─────────                  ─────────
1. 工作台选中单词          → 高亮选中                  → 选中状态
2. 点击"问 AI"             → 右侧面板展开              → AI 面板打开
                           → 上下文条显示当前原文
3. 输入问题                → 显示在输入框              → 问题输入
4. 点击"发送"              → 消息列表追加用户消息      → 请求发送
                           → 显示流式输出              → AI 回复中
5. （等待）                → 流式输出完成              → 回复完成
6. 点击"采集术语"          → Toast "已采集"            → 采集队列+1
7. 点击"关闭面板"          → 面板收起                  → 返回工作台
```

**关键决策点**：
- 步骤 2 的上下文自动带入当前原文/译文
- 步骤 4 的流式输出支持中断
- 步骤 6 的"采集术语"将 AI 解释中的关键术语入队

| 约束 | 说明 |

| 回调连接 | UI 通过 callback 连接到 services 层 |
